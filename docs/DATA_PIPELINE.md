# Збір даних про художника однією командою

Одна команда шукає все про художника: картини, мем-профілі, факти й біографію. Потім відкривається сторінка, де людина все перевіряє, і кнопка «Опублікувати» записує схвалене в базу.

```
enrich_artist.py ─┬─ 1. paintings  Wikidata + Commons → нові картини (без Gemini)
                  ├─ 2. profiles   Gemini дивиться на картину → мем-профіль
                  ├─ 3. facts      Gemini читає Вікіпедію → факти з дослівними цитатами
                  ├─ 4. bio        Gemini пише біографію, кожне речення з цитатою
                  └─ 5. review     сторінка http://127.0.0.1:8765 → ✅ / ❌ / ✏️ → «Опублікувати»
```

## Перед першим запуском

У `backend/.env` (цей файл не комітиться) мають бути:

```
AI_API_KEY=...              # ключ Gemini з Google AI Studio
AI_MODEL=gemini-3.8-flash   # або інша модель
```

Ключ Supabase потрібен лише тоді, коли публікуєш у спільну базу.

### Кілька моделей

Скрипти починають з `AI_MODEL`. Якщо модель перевантажена (503), упирається в ліміт (429) або не відповідає, вона «відпочиває» 5 хвилин, а запит іде до наступної моделі в списку:

```
gemini-3.8-flash → gemini-3.7-flash → gemini-3.5-flash → gemini-3.1-flash-lite
```

Безкоштовні ліміти рахуються окремо для кожної моделі, тож перемикання ще й додає квоти. Модель, яка недоступна для ключа (404), випадає зі списку. У кожному профілі, факті й біографії записано, яка модель їх написала. Профілі від `flash-lite` простіші, тож переглядай їх уважніше.

Свій список можна задати в `backend/.env`:

```
AI_FALLBACK_MODELS=gemini-3.5-flash,gemini-3.1-flash-lite   # порожньо = без запасних моделей
```

## Запуск

Для художника, який уже є в `data/seed/artists.json`:

```bash
backend/.venv/bin/python data/scripts/enrich_artist.py mykola-pymonenko
```

Для нового художника використай його Wikidata id. Це код `Q…` з адреси його сторінки на wikidata.org. Скрипт сам додасть художника, якщо той помер у 1955 році або раніше (тоді його картини є суспільним надбанням в Україні):

```bash
backend/.venv/bin/python data/scripts/enrich_artist.py Q12345678
```

Тут `Q12345678` — це приклад, підстав справжній код художника.

Що можна додати до команди:

| Опція | Що робить |
|---|---|
| `--limit 20` | скільки нових картин профілювати (за замовчуванням 12) |
| `--model gemini-3.1-flash-lite` | швидша модель для всіх етапів |
| `--only paintings,profiles` | запустити лише ці етапи |
| `--skip bio` | пропустити етап |
| `--redo facts` | запустити етап заново, хоча чернетка вже є |
| `--url https://…` | додаткове джерело для фактів і біографії |
| `--no-review` | не відкривати сторінку перевірки |

Команду можна запускати повторно. Зроблені етапи пропускаються, а рішення, які ти вже прийняла на сторінці, зберігаються.

Окремо сторінка перевірки відкривається так:

```bash
backend/.venv/bin/python data/scripts/review_server.py --artist mykola-pymonenko
```

## Що перевіряє скрипт (автоматичний скринінг)

**Картини.** Скрипт залишає лише ті, де:
- файл на Commons має ліцензію «суспільне надбання» або CC0;
- довша сторона зображення має щонайменше 800 px;
- рік картини входить у роки життя художника (інакше рік прибирається з позначкою).

Картини, які вже є в каталозі, не змінюються.

**Мем-профілі.** У профілі обов'язково мають бути опис і ситуації для мемів. Чутливі картини позначаються.

**Факти.** Факт проходить, лише якщо:
- цитата дослівно є в джерелі й не скорочена;
- кожне число з факту є в цитаті;
- факт про картину містить у цитаті назву цієї картини.

**Біографія.** Кожне речення має підтверджувальну цитату. Речення, дослівно скопійовані з джерела, позначаються.

Усе, що скрипт відсіяв, видно на сторінці в розділі «Відсіяно автоматично».

## Що перевіряє людина на сторінці

- **Картини:** опис збігається з зображенням, назва українська й правильна, ситуації для мемів добрі. Можна виправити назву, опис, ситуації й теги.
- **Факти:** текст відповідає цитаті. Щоб факт потрапив у базу, потрібні ✅ і **друге джерело**.
- **Біографія:** текст, місце народження, портрет.

Кожна зміна одразу зберігається в чернетки:
- `data/artwork_drafts/`
- `data/facts_drafts/`
- `data/bio_drafts/`

Сторінку можна закрити й повернутися до неї пізніше.

## «Опублікувати»

Кнопка запускає по черзі:

1. схвалені картини → `data/artworks_meme_descriptions.json` → `import_profiles.py` → `data/seed/artworks.json`;
2. `process_images.py` → `data/images/` (зображення, які вже скачалися під час профілювання, повторно не завантажуються);
3. `extract_facts.py import` → `data/seed/facts.json` (сюди потрапляють і факти про щойно додані картини);
4. `extract_bio.py import` → `data/seed/artists.json` + портрет;
5. ембединги: `embed_artworks.py --local-only`.

Галочка «Також записати в Supabase» додатково запускає `upload_to_supabase.py` і `embed_artworks.py`. Це спільна база всієї команди, тож попередь колег. Після цього перезапусти бекенд на Render.

Нічого не комітиться автоматично. Після публікації закоміть:
- `data/seed/*.json`
- `data/images/`
- `data/artworks_meme_descriptions.json`

## Якщо щось пішло не так

| Повідомлення | Що робити |
|---|---|
| `Wikimedia просить зачекати (429)` | Wikimedia обмежує ботів. Скрипт чекає сам. Якщо картина не скачалася, запусти ще раз пізніше. |
| `перевантажений (503) → беру …` | усе гаразд: скрипт сам перейшов на іншу модель |
| `… → чекаю 30 с` | зараз зайняті всі моделі; скрипт чекає сам |
| `Gemini так і не відповів` | запусти ще раз пізніше: готове збережено, скрипт доробить лише решту |
| `process_images.py завершився з помилкою` | картина поки показується з Wikimedia; натисни «Опублікувати» ще раз пізніше |
| `чекає на картину Q…` | факт про картину, яку ще не схвалено; схвали картину й опублікуй |
